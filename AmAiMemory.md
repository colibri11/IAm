# Архитектура системы памяти для LLM-агентов

## Спецификация на основе функциональной концепции личности

**Автор концепции: Сергей Омаров**

**Дата: Апрель 2026**

---

## 1. Постановка проблемы

Контекстное окно LLM — плоское хранилище (последовательность токенов). Наличие текста в контексте не равно удержанию конструкции. При работе со сложными многомерными системами знаний LLM вынуждена на каждом шаге интерпретации совершать редукцию: выбирать, на какие связи обратить внимание, а какие оставить фоном. Этот выбор неизбежно приводит к искажениям — ложным тождествам, ложным разделениям, потере связей между элементами.

Увеличение объёма контекстного окна проблему не решает. Объём хранения не равен качеству оперирования. Это подтверждается экспериментально: LLM с полным текстом сложного документа в контексте систематически создаёт редукционные ошибки при интерпретации.

## 2. Ключевой принцип

Принцип заимствован из функциональной концепции личности:

- **Текущий контекст не подлежит компрессии**, пока он входит в активный когнитивный процесс.
- **За пределами активного контекста** — семантически управляемое сжатие с сохранением направленности.
- **Память — не retrieval-механизм**, а система сохранения структуры связей, при которой новый акт мышления возникает из уже прожитого, а не почти заново.

## 3. Архитектура

Система состоит из трёх компонентов:

### 3.1. Граф знаний (хранение)

Единый граф. Не несколько слоёв, а один граф с типизированными узлами и рёбрами. Разделение на «онтологический», «эпизодический», «проектный» контексты — это не свойство графа, а свойство проекции. Один и тот же узел может быть востребован в разных контекстах. Промежуточный слой при формировании проекции решает, что включить, на основании топологии и весов, а не на основании принадлежности узла к «слою».

#### 3.1.1. Узлы

Каждый узел представляет понятие, сущность или утверждение.

Атрибуты узла:

- **id** — уникальный идентификатор.
- **content** — содержание (естественный язык). Единственное поле, содержащее семантику.
- **confidence** — вещественный коэффициент достоверности [0.0 — 1.0]. Заменяет дискретные градации (подтверждено / гипотеза / устарело). Непрерывная шкала исключает редукцию при классификации.
- **created_at** — момент создания.
- **updated_at** — момент последнего изменения.

#### 3.1.2. Рёбра

Каждое ребро представляет связь между двумя узлами.

Типы рёбер (фиксированное множество, не расширяется без явного решения):

| Тип | Значение |
|-----|----------|
| `IDENTITY` | A есть B, выраженное иначе |
| `PART_OF` | A является частью B, но не тождественно B |
| `NOT_IDENTICAL` | A не тождественно B (явная защита от ложного схлопывания) |
| `IMPLIES` | Из A следует B |
| `CONFLICTS` | A противоречит B |
| `DEPENDS_ON` | A зависит от B (без A→B не работает) |
| `EXTENDS` | A расширяет B (добавляет измерение, не отменяя B) |

Атрибуты ребра:

- **type** — тип из фиксированного множества.
- **weight** — вещественный коэффициент силы связи [0.0 — 1.0].
- **identity_degree** — дополнительный атрибут для рёбер типа `IDENTITY` [0.0 — 1.0]. Различает полное тождество (1.0), контекстное тождество, операциональную эквивалентность и приблизительное сходство (ближе к 0.0). Защита от ложного схлопывания синонимии.
- **created_at** — момент создания.
- **updated_at** — момент последнего изменения.
- **valid_from / valid_to** — временной интервал актуальности (null означает бессрочность).

#### 3.1.3. Временная ось

Временная ось — часть логики графа, а не метаданные.

Одно и то же ребро в разные моменты может иметь разный вес. Это не два разных ребра, а одно ребро с историей. Реализация — через версионирование: каждое изменение веса или статуса ребра создаёт запись в истории, предыдущее значение сохраняется. Это предотвращает комбинаторный рост графа при сохранении полной траектории изменений.

Временная ось позволяет:

- восстановить состояние графа на любой момент в прошлом,
- отследить, как менялась связь между понятиями,
- различить актуальное знание и историческое.

### 3.2. Промежуточный LLM-слой (оператор графа)

#### 3.2.1. Принцип работы

Этот слой — оператор графа, а не интерпретатор содержания. Он работает с топологией: узлы, рёбра, типы связей, веса. Не с семантикой того, что в узлах написано.

Аналогия: вырожденная воля (термостат). Инерция связей, а не инерция смыслов.

#### 3.2.2. Допустимые операции

Оператор графа выполняет только следующие операции:

- **Выбор подграфа по запросу.** Определяет, какие узлы и рёбра релевантны, на основании: типов рёбер в запросе, расстояния в графе от точки входа, весов рёбер и коэффициентов достоверности узлов, временного интервала актуальности.
- **Ограничение глубины разворачивания.** По весам и расстоянию, не по «пониманию важности».
- **Различение классов запросов.** По формальным признакам запроса (структура, ключевые слова, указанные типы связей), а не по интерпретации содержания.
- **Сериализация подграфа** в формат для передачи целевой LLM.

#### 3.2.3. Запрещённые операции

- Интерпретация содержания узлов.
- Оценка «важности» на основании семантики.
- Построение новых смысловых связей, не существующих в графе.
- Перефразирование содержания узлов.

### 3.3. Сериализация (формат передачи)

#### 3.3.1. Формат — JSON с жёсткой схемой

Не DSL, не естественный язык. JSON выбран по следующим основаниям:

- **Валидируемость.** JSON Schema обеспечивает автоматическую проверку структуры.
- **Однозначность.** Связи выражены явно, не допускают переинтерпретации.
- **Расширяемость.** Новые атрибуты добавляются без ломки формата.
- **Совместимость.** LLM обучена на огромном корпусе JSON и обрабатывает его с минимальными потерями.
- **Компактность.** Существенно меньше токенов, чем XML, при тех же гарантиях.

#### 3.3.2. Пример структуры

```json
{
  "projection_context": "запрос о связи воли и перехода",
  "timestamp": "2026-04-13T15:30:00Z",
  "nodes": [
    {
      "id": "n001",
      "content": "Воля",
      "confidence": 0.95
    },
    {
      "id": "n002",
      "content": "Переход между положениями в смысловых измерениях",
      "confidence": 0.95
    },
    {
      "id": "n003",
      "content": "Инерция перехода",
      "confidence": 0.90
    }
  ],
  "edges": [
    {
      "type": "PART_OF",
      "source": "n001",
      "target": "n002",
      "weight": 0.95
    },
    {
      "type": "IDENTITY",
      "source": "n001",
      "target": "n003",
      "weight": 0.85,
      "identity_degree": 0.70
    }
  ]
}
```

В этом примере: воля является частью перехода (не тождественна ему). Воля и инерция перехода — операционально эквивалентны (identity_degree 0.70), но не полностью тождественны. Целевая LLM получает эту структуру и видит связи явно, без необходимости достраивать их самостоятельно.

## 4. Контур валидации

Двухуровневая алгоритмическая валидация. Оба уровня работают без интерпретации содержания.

### 4.1. Первый уровень — структурная валидация (JSON Schema)

- Все обязательные поля присутствуют.
- Типы рёбер принадлежат фиксированному множеству.
- Веса и коэффициенты лежат в допустимом диапазоне [0.0 — 1.0].
- Идентификаторы узлов в рёбрах ссылаются на существующие узлы.
- Временные метки валидны.

Выполняется мгновенно, одним вызовом валидатора.

### 4.2. Второй уровень — графовая валидация (алгоритмический обход)

- **Связность.** Нет изолированных подграфов (все узлы достижимы).
- **Противоречия.** Нет одновременных `IDENTITY(A,B)` и `NOT_IDENTICAL(A,B)`.
- **Циклы.** Нет петель в рёбрах `PART_OF` (A часть B, B часть A).
- **Весовые аномалии.** Нет узлов с нулевой достоверностью, на которые ссылаются рёбра с высоким весом.
- **Темпоральная консистентность.** Нет рёбер с `valid_to` в прошлом, включённых в текущую проекцию.

### 4.3. Контур коррекции

При невалидности на любом из уровней:

1. Ошибка формализуется (какое именно правило нарушено, какой узел или ребро).
2. Ошибка возвращается промежуточному LLM-слою в промпте.
3. Промежуточный слой генерирует исправленную проекцию.
4. Повторная валидация.

Контур работает автоматически, без участия человека, без интерпретации содержания. Максимальное число итераций ограничено (например, 3), после чего система сигнализирует о неразрешимой ошибке.

## 5. Критически важные связи

Экспериментально установлено (в ходе работы с трактатом «Я есть»), что основная доля редукционных ошибок LLM приходится на два типа связей:

1. **«A есть B, выраженное иначе»** — ложные тождества. LLM схлопывает различное в одно.
2. **«A является частью B, но не тождественно B»** — ложные разделения или ложные отождествления части с целым.

Поэтому рёбра типов `IDENTITY`, `PART_OF` и `NOT_IDENTICAL` являются приоритетными при формировании проекции. Промежуточный слой должен включать их в проекцию всегда, когда запрошенные узлы связаны рёбрами этих типов, независимо от глубины разворачивания.

## 6. Принципы из концепции личности, применённые как спецификация

| Принцип из трактата | Применение в архитектуре |
|---|---|
| Текущий контекст не подлежит компрессии | Проекция, переданная в контекст целевой LLM, не сжимается далее |
| За пределами контекста — семантически управляемое сжатие с сохранением направленности | Промежуточный слой решает, что развернуть, а что передать как указание на связь |
| Память сохраняет не буквальность, а смысловую направленность | Граф хранит связи и веса, а не полные тексты всех разговоров |
| Конструкция не допускает редукции | Формат сериализации делает связи явными, не оставляя их на достраивание целевой LLM |
| Воля — инерция перехода, инвариантная ко времени | Временная ось графа сохраняет историю изменений, не создавая дубликатов |
| Различение возможно только в пространстве определения | Типизация рёбер задаёт пространство, в котором связи могут быть различены |

## 7. Ограничения и следующие шаги

### Текущие ограничения

- Интерфейс LLM принимает только плоский текст. JSON-сериализация — костыль, неизбежный на данном этапе.
- Промежуточный LLM-слой сам подвержен галлюцинациям при формировании проекции. Двухуровневая валидация снижает риск, но не устраняет полностью.
- Схема типов рёбер зафиксирована. Расширение требует явного решения и пересмотра валидационных правил.

### Следующие шаги

1. Определить JSON Schema для графа и проекций.
2. Реализовать двухуровневый валидатор.
3. Реализовать промежуточный LLM-слой с жёстко ограниченным промптом (только топологические операции).
4. Провести эксперимент: загрузить трактат «Я есть» в граф, сформировать проекцию, передать целевой LLM, проверить, воспроизводятся ли редукционные ошибки.
5. По результатам эксперимента — откалибровать пороги весов, глубину разворачивания и приоритеты типов рёбер.
